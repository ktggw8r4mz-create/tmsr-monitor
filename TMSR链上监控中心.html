预测方法与边界

评分 = 资金面/结构面信号的规则推断（售价倒挂幅度、锁仓缺失、订单敞口、单点权限），反映"事件发生的结构性概率"，不代表时间点预测。本机部署后，predict.py 每 24 小时基于最新快照重算并写入 predict.json；本页将自动读取刷新，Telegram 推送时附带预测摘要。

本机部署状态 macOS launchd 已内置

  1. 定时采集：com.hule.tmsr.monitor 每 24 小时自动执行 monitor_all → tmsr_monitor → predict → notify，日志在 logs/run.log。
  2. Telegram 推送：编辑 config.json 填入 bot_token / chat_id 即激活；任意地址余额、合约状态、价格变动即推送。
  3. 风险预测：predict.py 每轮重算 5 项事件概率，写入 predict.json，本页"预测"Tab 自动刷新。
  4. 启停：安装 install_monitor.sh / 卸载 uninstall_monitor.sh；查看状态 launchctl list | grep tmsr。

服务器部署指南 让监控 7×24 可查

准备服务器：任意 Linux 云主机（或本机 24h 开机电脑），需安装 python3（含 requests/urllib）与 Nginx 或宝塔。
上传文件：把 TMSR链上监控中心.html、monitor_all.py、tmsr_monitor.py 放到站点目录（如 /var/www/tmsr/），把监控中心 HTML 重命名为 index.html。
配置 Nginx：
server {
  listen 80;
  server_name 你的域名或IP;
  root /var/www/tmsr;
  index index.html;
  location / { try_files $uri $uri/ =404; }
}
定时采集（cron）：
# 每 24 小时拉一次链上数据（与当前本机周期一致），输出 data.json
0 9 * * * cd /var/www/tmsr && python3 monitor_all.py
0 9 * * * cd /var/www/tmsr && python3 tmsr_monitor.py >> logs/monitor.log 2>&1
monitor_all.py 会把 all_addresses.json 写到同目录，供页面 fetch 实时刷新（部署后打开页面即自动读取最新数据）。
可选 · 异常告警（Telegram/钉钉 Webhook）：在 cron 行追加推送逻辑：当健康度低于阈值、任一 owner 钱包余额骤降或 salePrice 偏离 >30% 时，调用 webhook 发送警报消息。

实时刷新原理

本页内置 2026-10-19 23:25 快照作为首屏数据。部署到服务器后，页面 JS 会每 60 秒尝试读取同目录 all_addresses.json（由 cron 定时生成）：成功则自动覆盖全部数值并更新"最后刷新时间"；失败则保持快照并显示"离线快照"标记。这样手机浏览器随时打开都能看到最新链上状态。

fetch('./all_addresses.json?t='+Date.now())
  .then(r=>r.json()).then(applyData)
  .catch(()=>showOffline());
